# Specialist Review Packets

## Purpose

These packets convert the open rows in `specialist-review-register.csv` into bounded external-review assignments. They do not claim that specialist review has occurred.

## Review packets

| Packet | Register rows | Primary purpose |
|---|---|---|
| [Tamil, Textual and Performance Review](tamil-textual-and-performance-review.md) | `SR-001`–`SR-003`, `SR-007`–`SR-009` | Tamil performance, primary-text compatibility, Bharathidasan perspective, food language, consent and trauma |
| [Religion and Philosophy Review](religion-and-philosophy-review.md) | `SR-004`–`SR-005` | Buddhist doctrine, rebirth, causation, inference and rival schools |
| [History and Material Culture Review](history-and-material-culture-review.md) | `SR-006`, `SR-010`–`SR-012` | Institutions, maritime world, costume, ritual and animal ethics |

| [Response Template](specialist-response-template.md) | All | Consistent findings, severity, evidence and disposition |
| [Reviewer Invitation and Intake Kit](reviewer-invitation-and-intake.md) | All | Candidate invitation, accepted-scope intake and returned-response handling |

Use the [reviewer-selection rubric](../reviewer-selection-rubric.csv) before
sending a packet. A candidate is not an assigned reviewer until acceptance,
scope and conflict information are recorded.

## Status vocabulary

- `READY_FOR_EXTERNAL_REVIEW`: the packet is complete enough to send.
- `IN_REVIEW`: a named reviewer has accepted the assignment.
- `CHANGES_REQUESTED`: the reviewer has returned actionable findings.
- `APPROVED_WITH_NOTES`: no blocking concern remains, but qualifications must stay visible.
- `APPROVED`: the stated scope has passed.
- `BLOCKED_EVIDENCE`: the reviewer cannot decide without a missing edition, scan or other source.

Only a named reviewer or documented institutional review can move a row to an approval state. Internal preparation does not count as specialist approval.

## Submission rules

1. Give the reviewer only lawful source access.
2. Record the edition, page, line or stable digital locator used.
3. Separate direct textual correction from interpretive preference.
4. Identify every affected `TERM-*`, `EV-*`, `AD-*`, `SC-*`, scene and language edition.
5. Do not edit only the English or only the Tamil screenplay.
6. Preserve rejected and superseded findings in the audit trail.
7. Run all repository validators after an approved change.
